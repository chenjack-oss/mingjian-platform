# 深度调研

## 什么时候用这个技能

**只有同时满足下面两条时才用：**

1. 问题确实需要外部事实 / 行业数据 / 新闻动态，凭已有知识答不准；
2. 用户期望一份**成体系、可核验**的成果（而不是三句话的结论）。

反面例子（这些**不要**走深度调研，直接答即可）：

- 「RRF 的 k 一般取多少」→ 概念性问题，直接答
- 「帮我看看这段代码有什么问题」→ 不需要检索
- 「你好」「谢谢」→ 闲聊
- 任何凭已有知识就能答准的问题

**这条边界是整个平台的立身之本。**
旧版本把调研当成系统的唯一人格（提示词强制"拆 3~5 个子问题 + 正文不少于 1000 字"），
结果每一句话都被做成一份报告。现在调研只是一个**可被调用的技能**。

## 什么时候产出文档

**用户明确要文件，或者问题本身需要留档时才写文档。**

- 用户说「写一份报告 / 出个文档 / 整理成文件」→ 写
- 用户只是问一个问题，答完即可 → **不要**写文档，直接回答
- 拿不准就先答，再补一句「需要的话我可以整理成文档」

## 流程

### 1. 澄清范围（只在真正模糊时）

主题、时间/地域范围、输出格式。缺哪个问哪个，**一次最多问两个**，不要连环追问。

### 2. 拆解与规划

把问题拆成 3~5 个可独立检索的子问题，维度参考：现状 / 数据 / 趋势 / 风险 / 对比。
用 todo 工具把计划写出来，让用户看到进度。

### 3. 检索

- 每个子问题用**不同关键词**检索；相同关键词不要重复搜（工具层有缓存和熔断，重复会被拒）
- 由浅入深：先拿到初步结果，再针对缺口深入
- 工具返回「已达搜索预算上限」或「未检索到结果」时**立即停止检索**，基于已有信息总结
- 搜索预算默认是每次会话 12 次，用完就没了，别浪费在重复 query 上

### 4. 核验

- 信源分级：**权威源（政府 / 上市公司 / 头部媒体）> 普通媒体 > 自媒体论坛**；冲突时按级别裁决，并在正文显式标注分歧
- 不同信源结论冲突时**并列呈现**，不要自行和稀泥
- 检索不到就写「未检索到公开数据」——**禁止用常识或记忆编造数字**

### 5. 成稿

文档要求（要写的时候才适用）：

- 有结论、有数据、有来源
- 每个关键数据/结论附**完整来源 URL**（`https://...` 全链接，不能只写来源名）+ 发布时间
- URL 必须**逐字复制**自检索结果里的原始 url 字段，禁止凭印象拼接、改写、简化
- 涉及薪资、价格、排名等强时效数据，标注数据截止时间
- 末尾附「未检索到的内容清单」（诚实缺口）

## 硬性红线

1. **禁止编造 URL**。系统会在落盘前比对正文链接与本次检索登记的真实链接，
   对不上的会在文末「引用溯源校验」章节里被显式列出 —— 那是公开处刑，别踩。
2. **禁止编造具体数字、比例、样本量**。没查到就写"未检索到"。
3. **不要在拿到检索结果之前调用 write_document**，严禁用「等待子任务完成」占位符凑内容。
4. 不要把文档生成工作交给子智能体，成稿由你统一产出。
5. 汇报进度时只说「已创建」，不要把内部路径暴露给用户。

## 停止准则

出现以下任一情况就停止检索、直接输出：

- 搜索预算耗尽
- 连续两次检索没有新增信息
- 已有信息足以回答核心问题（**不要为了凑篇幅继续搜**）

宁可给出一份"信息有限但每条都可核验"的短报告，
也不要一份"看起来很全但一半是编的"的长报告。
